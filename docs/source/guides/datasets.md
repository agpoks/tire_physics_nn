# Datasets

No dataset is committed to this repository, and nothing large downloads automatically.
Each source has a `scripts/download_<name>.py` that either fetches a small subset or
prints the exact manual steps and exits non-zero. Every experiment also runs on
in-repo synthetic data, so the framework is verifiable before any download succeeds.

## Source types — always labelled

Every dataset carries one of these labels, and the label is repeated in any results
table that uses it:

**real measurement**
: physical test bench or instrumented vehicle.

**simulated**
: generated by a vehicle-dynamics simulator.

**game telemetry**
: racing-game UDP/telemetry logs — illustrative only, **excluded from every
  quantitative claim**. A game's tire model is a design artefact, not a measurement.

**synthetic**
: generated in this repository by `make_synthetic`, `make_synthetic_transient`,
  `make_synthetic_vehicle` or `make_synthetic_graining`.

## Getting the data in

One call fetches what can be fetched unattended, then loads it:

```python
from tire_nn.data import registry

df = registry.get("synthetic_force", n=6000)      # always works
df = registry.get("f1_stints")                     # downloads via FastF1, no API key
df = registry.get("kit", root="data/raw")          # loads if present, else prints the steps
```

`fetch()` is deliberately conservative: it will not click a licence for you, use your
Kaggle credentials, or pull a multi-gigabyte archive on your behalf. When it cannot
proceed it raises with the exact steps rather than failing obscurely or silently
substituting something else:

```text
NotImplementedError: KIT inner-drum tire force transmission (dry asphalt) cannot be
fetched unattended.
  1. Open the RADAR4KIT page above.
  2. Accept the CC BY-NC-SA 4.0 licence and download the archive.
  3. Extract into data/raw/kit/ , keeping the folder structure.
  ...
  url: https://radar.kit.edu/radar/en/dataset/p0rr2jc5wmf0drf8
```

:::{tip}
**Start with `f1_stints`.** It is the only real dataset here that needs no manual step —
FastF1 is MIT-licensed and needs no API key — so it is the fastest way to see the
framework working on real measurements.
:::

An unverifiable dataset citation is worse than a missing one, which is why the
unverified entries are flagged in the registry itself rather than quietly listed.

## The canonical schema

Every adapter returns a `pandas.DataFrame` with these columns, in **SI units** and the
project-wide **SAE sign convention**. Converting once, at the adapter boundary, is what
lets a single training script run on a drum test bench, a bicycle-tyre rig and a
small-scale race car.

| column | unit | required | note |
|---|---|---|---|
| `alpha` | rad | yes | slip angle |
| `kappa` | – | yes | slip ratio (0 for a pure-lateral rig) |
| `Fz` | N | yes | vertical load, > 0 |
| `Fx`, `Fy` | N | target | at least one for direct-force data |
| `Mz` | N·m | no | aligning moment |
| `vx` | m/s | no | required for transient data |
| `p` | Pa | no | inflation pressure |
| `gamma` | rad | no | camber |
| `Ts`, `Tc`, `T_road`, `T_air` | K | no | temperatures |
| `mu_ref` | – | no | reference friction |
| `t` | s | sequences | timestamp |
| `sequence_id` | int | sequences | splits never cut inside one |
| `tire_id` | str | yes | compound/condition → embedding index |
| `source` | str | yes | dataset tag |

Stint-level degradation data uses a third schema (`tire_nn/data/lap_degradation.py`)
with `tyre_age`, `compound`, `lap_time`, `track_temp`, `air_temp` and `fuel_frac`.
Notably it has **no tyre-state column**, because nobody measures one — see
[Degradation from stint data](../physics/degradation).

Vehicle-level data uses a second schema (`tire_nn/data/vehicle.py`) with `vx, vy, r,
ax, ay, r_dot, delta, omega_FL..RR`, and the vehicle geometry in the sidecar metadata.

`validate_schema` enforces the contract — including a check that `alpha` is not
accidentally in degrees, which is the single most common unit bug in tire data.

## Adding an adapter

```python
def load_myrig(root, **kw) -> pd.DataFrame:
    df = pd.read_csv(Path(root) / "myrig.csv")
    out = pd.DataFrame({
        "alpha": np.deg2rad(df["slip_angle_deg"]),
        "kappa": df["slip_ratio"],
        "Fz": df["Fz_N"],
        "Fy": df["Fy_N"],
        "p": df["pressure_bar"] * 1e5,
        "tire_id": df["compound"],
        "source": "myrig",
    })
    # If the source uses the opposite sign convention, convert here — once:
    # out = flip_sign_convention(out)
    return validate_schema(out, ("Fy",))
```

Document the source's sign convention in the adapter docstring. That one sentence
prevents the most expensive class of bug in this domain.
